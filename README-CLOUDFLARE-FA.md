# راه‌اندازی نهایی دابرناز روی Cloudflare Pages + D1

این بسته، لایهٔ بک‌اند را به پروژهٔ فعلی اضافه می‌کند؛ ظاهر سایت و مسیرهای API موجود در `app.js` حفظ شده‌اند.

## چه چیزهایی فعال می‌شوند؟

- ثبت‌نام با نام، ایمیل و رمز عبور؛ رمز با PBKDF2 هش می‌شود و به‌صورت خام ذخیره نمی‌شود.
- ورود/خروج و نگهداری نشست با کوکی `HttpOnly` و `Secure` روی HTTPS.
- ذخیره شناسه کاربر، آمار بازی و BGC در D1.
- به‌روزرسانی نام نمایشی حساب.
- ثبت نتایج رسمی سنگ‌کاغذ‌قیچی و دوز با نشست مسابقه و محاسبه حرکت حریف در سرور؛ نتیجه دلخواه ارسالی از مرورگر پذیرفته نمی‌شود.
- اتاق‌های دبرنا بدون سقف کلی بازیکن یا کارت؛ هر حساب در هر سانس حداکثر ۵ کارت می‌خرد. اولین خرید، زمان ثابت ۱۵۰ ثانیه‌ای را آغاز می‌کند و پس از پایان آن، اتاق خودکار وارد بازی می‌شود.
- بازی پس از پایان مهلت خرید و با حداقل ۵ شرکت‌کننده آغاز می‌شود. مبلغ جایزه یک خط و دبرنای کامل در صفحه اتاق نمایش داده می‌شود و اگر چند نفر هم‌زمان برنده شوند، مبلغ جایزه همان مرحله بین آن‌ها تقسیم می‌شود.
- ثبت زمان شروع/پایان خرید، مبلغ جمع‌شده، شمار بازیکنان و کارت‌ها و پرداخت‌های سانس در سرور و تاریخچه D1.
- ذخیره نام و شناسه برندگان خطی و کامل سانس‌های جدید در تاریخچه D1.
- ثبت دعوت‌ها و پاداش خودکار هر ۵ دعوت موفق: ۲۰٬۰۰۰ تومان اعتبار داخلی کیف پول و ۵ BGC.
- ثبت و نمایش تیکت‌های هر کاربر در حساب خودش.
- ثبت‌نام سروری تورنمنت ساده (۲۰ BGC) و بینگو تورنمنت (۱۰۰ BGC)، با صف ۳۰نفره و جلوگیری از ثبت‌نام تکراری.
- ساخت/تکمیل جدول‌های جانبی و ستون‌های جدید دیتابیس در اولین درخواست API؛ نیازی به وارد کردن SQL جداگانه نیست.

## نصب روی پروژهٔ GitHub موجود

۱. در ریشهٔ مخزن `nimamoshfegh8/dabernaz` باید پوشهٔ `functions/` و فایل‌های اصلی پروژه وجود داشته باشند. تنظیمات فعلی استقرار از داشبورد Cloudflare Pages خوانده می‌شوند؛ در این مخزن برای Build فعلی به فایل `wrangler.toml` نیاز نیست.

۲. در Termux، داخل پروژه اجرا کن:

```bash
cd ~/dabernaz
npm run build:pages
```

این دستور پوشهٔ `dist` را می‌سازد. فقط فایل‌های لازم برای نمایش سایت داخل `dist` کپی می‌شوند؛ فایل‌های قدیمی PHP، Node و پوشهٔ خصوصی در خروجی عمومی منتشر نمی‌شوند.

۳. تغییرات را به GitHub بفرست:

```bash
git add .
git commit -m "Add Cloudflare D1 backend"
git push
```

۴. در Cloudflare برو به:

**Workers & Pages → dabernaz → Settings → Builds**

مقادیر را این‌طور تنظیم کن:

- Build command: `npm run build:pages`
- Build output directory: `dist`
- Root directory: خالی / ریشه Repository

اگر Wrangler config از داشبورد به‌عنوان تنظیم اصلی پروژه استفاده می‌شود، این مقادیر باید با `wrangler.toml` هم‌خوان باشند.

۵. دیتابیس را به Pages Function متصل کن:

**Workers & Pages → dabernaz → Settings → Bindings → Add → D1 database**

- Variable name: `DB`
- D1 database: `dabernaz-db`
- محیط Production را فعال کن؛ اگر Preview هم داری، برای آن هم Binding را تنظیم کن.

ذخیره کن و یک بار **Redeploy** بزن تا Binding وارد اجرای Function شود.

## سیستم صوتی فارسی دابرنا

در کد وب، تنظیمات و اتاق‌ها از یک Audio Manager مشترک استفاده می‌کنند. ترتیب انتخاب موتور:

1. بستهٔ MP3 صدای **Kenerate Sage Woman**، فقط وقتی فایل و مانیفست ۹۰ شماره کامل و معتبر باشند.
2. در APK اندروید، پل بومی **Android TextToSpeech** و صدای فارسی نصب‌شده روی گوشی.
3. در وب/PWA، موتور `SpeechSynthesis` مرورگر، در صورتی که صدای فارسی در دسترس باشد.

موتور بومی Android یا موتور مرورگر، صدای ضبط‌شدهٔ Sage Woman نیستند و کیفیت آن‌ها به دستگاه وابسته است. آماده بودن endpoint یا Build هم به معنی آماده بودن بستهٔ صوتی نیست؛ `/api/voice/health` فقط قرارداد فایل‌ها را معرفی می‌کند و آمادگی واقعی فقط پس از دریافت، decode و اعتبارسنجی سمت کاربر مشخص می‌شود.

### وضعیت فعلی بستهٔ Sage Woman

در مخزن فعلی فقط مانیفست غیرفعال وجود دارد؛ `configured=false` است، فهرست ۹۰ شماره خالی است و فایل `assets/voice/sage-woman.mp3` موجود نیست. بنابراین این نسخه هنوز صدای Sage Woman را ندارد.

برای تکمیل بسته:
1. فایل `docs/kenerate-90-number-script.txt` را باز کن و ۹۰ خط را به Voice Studio حساب Kenerate بده.
2. صدای **Sage Woman** و زبان فارسی را انتخاب کن؛ سرعت و pitch را مطابق نمونهٔ تأییدشده نگه دار.
3. خروجی کامل MP3 را دریافت و در همین گفتگو بارگذاری کن تا بتوان آن را در پروژه قرار داد و برای هر شماره زمان شروع/مدت معتبر ساخت.
4. فایل نهایی باید در `assets/voice/sage-woman.mp3` قرار گیرد و `assets/voice/sage-woman.json` باید برای هر شمارهٔ ۱ تا ۹۰ یک clip معتبر داشته باشد. متن هر clip دقیقاً مطابق فایل اسکریپت باشد و مقدار `audioDurationSeconds` در مانیفست، انتهای آخرین clip را پوشش دهد.

یک نمونهٔ ۱٫۱۵ ثانیه‌ای فقط یک عبارت را در بر می‌گیرد و نمی‌توان از آن تلفظ طبیعی ۹۰ شماره را بازسازی کرد. فایل MP3 کامل و مانیفست زمان‌بندی‌شده هنوز باید فراهم شوند.

### تست و انتشار

تست کد UI، Audio Manager و پل Android در `scripts/voice-ui-smoke.mjs` اجرا می‌شود. تست `scripts/voice-pack-validation.mjs` عمداً انتشار را **ناقص** اعلام می‌کند و CI را ناموفق می‌کند تا بدون MP3 کامل و ۹۰ clip معتبر، کسی Release را کامل تلقی نکند. برای اجرای محلیِ تست‌های غیرانتشاری می‌توان `node scripts/voice-pack-validation.mjs --allow-pending` اجرا کرد؛ این گزینه CI را دور نمی‌زند و بسته را کامل نمی‌کند.

## آزمایش نهایی

این نشانی را باز کن:

`https://dabernaz.pages.dev/api/health`

پاسخ موفق باید چیزی شبیه این باشد:

```json
{"ok":true,"service":"dabernaz","backend":"cloudflare-pages-functions","database":"D1","mode":"ready"}
```

در اولین درخواست API، Worker جداول و ستون‌های موردنیاز را به‌صورت خودکار بررسی و تکمیل می‌کند. سپس از صفحه حساب کاربری یک حساب آزمایشی بساز، خارج شو و دوباره وارد شو.

## نکات مهم و محدودیت‌ها

- این نسخه ورود و حساب کاربری را به D1 وصل می‌کند؛ پرداخت/برداشت پول واقعی و درگاه بانکی همچنان فعال نیست.
- موجودی پولی در این نسخه صفر می‌ماند. BGC فقط امتیاز مجازی است و قابل نقدکردن یا برداشت نیست.
- شروع اتاق دبرنا ۱۵۰ ثانیه پس از اولین خرید انجام می‌شود. هیچ سقف کلی برای تعداد بازیکنان یا کارت‌های اتاق وجود ندارد؛ محدودیت ۵ کارت برای هر حساب در هر سانس سمت سرور اعمال می‌شود.
- صف ثبت‌نام تورنمنت، ظرفیت و کسر BGC فعال است؛ اما اجرای خود مسابقه، قوانین تعیین برنده و تقسیم جایزه تورنمنت هنوز نیازمند تعریف و پیاده‌سازی جداگانه است.
- تیکت‌های پشتیبانی در D1 ذخیره و برای صاحب حساب نمایش داده می‌شوند؛ پنل اپراتور و پاسخ‌دهی اپراتور هنوز تعریف نشده است.
- سنگ‌کاغذ‌قیچی و دوز در سرور اجرا و نتیجه نهایی توسط سرور محاسبه می‌شود. بازی‌های بینگو و حافظه در این نسخه تمرینی هستند و در آمار رسمی حساب اثر نمی‌گذارند.
- شروع و قرعه‌کشی با درخواست‌های دوره‌ای API پیش می‌رود؛ اگر تمام مرورگرها بسته باشند، Cron مستقل برای اجرای تایمر/قرعه‌کشی وجود ندارد. اولین درخواست پس از مهلت، اتاق را شروع می‌کند.
- قبل از استفاده عمومی، تست با کاربران واقعی، پشتیبان‌گیری و بررسی مقررات محلی لازم است.

## اگر Worker خطای D1 binding داد

اگر `/api/health` پیام «اتصال D1 تنظیم نشده است» داد، Binding با نام دقیق `DB` ذخیره نشده یا پروژه بعد از ذخیره Binding دوباره Deploy نشده است. نام متغیر باید دقیقاً `DB` باشد؛ لازم نیست هیچ شناسه یا رمز محرمانه‌ای در چت ارسال کنی.


## منبع اصلی کد منتشرشده

Cloudflare Pages از فایل‌های ریشهٔ مخزن استفاده می‌کند؛ به‌ویژه `index.html` و `app.js` و `styles.css` و پوشهٔ `assets/`، به‌علاوهٔ مسیرهای `functions/`. پوشه‌های `dabernaz_pro/` و `src/` نسخه‌های قدیمی/آزمایشی هستند و در Build فعلی Pages منتشر نمی‌شوند. پروژهٔ اندروید پشتیبانی‌شده نیز فقط `android/` است؛ `android-app/` بایگانی قدیمی است.
